# PyTorch学習方針：実装期における「T字型」学習プロトコル

## 目的
「完璧な理論書を書くこと」ではなく、**「論文の数式とPyTorchのコードを脳内で1対1対応させること」**。最終目標であるDiffusion Model実装まで、迷わず最短距離で駆け抜けるためのルール。

---

## 横の軸（Breadth）：テンソルの「Shape」による全体俯瞰
数式の完全理解は後回しにし、**データの流れ（形状変化）を完全に追跡**してネットワークの「設計思想（構造）」を読み解く。

* **必須ルール**
  * 全ての層（Layer）を通過した直後に、必ず `print(x.shape)` を仕込む。
  * 入力バッチが、どのように圧縮・変形され、最終的な出力形状になるかをマップ化する。
* **なぜこれで良いのか？**
  * 深層学習は「巨大な行列の次元変換パズル」。微分の数式を追わなくても、Shapeの変化さえ見れば「ここで空間情報が潰された（Flatten）」「ここで特徴が抽出された（Conv）」というアーキテクチャの意図が完全に把握できるため。

---

## 縦の軸（Depth）：深掘りする「3つのトリガー」
「なぜこの数式なのか？」を掘り下げるのは、**人間の意志（こう学習させたい）が数式としてダイレクトに反映される以下の3箇所のみ**に限定する。

1. **損失関数（Loss）が出たとき**
   * *理由:* 「モデルが何を目的としているか」を示す数式そのものだから。
   * *ゴール:* 数式（最尤推定など）と `nn.CrossEntropyLoss` 等の内部挙動（LogSoftmax等）が繋がったらストップ。
2. **テンソルの「特殊な結合・抽出」が出たとき**
   * *理由:* Attention、Skip結合など、Linear/Conv以外の特殊計算には必ず「人間の直感」が定式化されているから。
   * *ゴール:* 論文の数式（例: $QK^T$）が PyTorchの `torch.matmul` 等でどう実装されているか確認できたらストップ。
3. **確率分布から「サンプリング」するとき**
   * *理由:* VAEやDiffusion Modelにおいて、理論とコードを繋ぐ最大の架け橋（Reparameterization Trick等）だから。
